# axe 0.4.0 — `axe settings`: descriptor-only INI writes

## Context

axe today reads `ServerSettings.ini` for a curated set of seven keys (server name, rcon, max-players, password presence) and surfaces them in `axe status`. It has no write path. 0.4.0 lands the missing half: an `axe settings` verb family that mutates the small set of pre-boot config that determines **what the server looks like in the Steam server browser and the in-game Conan server browser**.

This is NOT a general INI editor. axe owns the descriptor; the operator owns everything else.

## The filter

axe's write surface is the intersection of:

1. **Visible in a server browser** — Steam external (A2S_INFO columns) OR Conan in-game (A2S_RULES decoded fields)
2. **Not runtime-mutable** — set at boot, can't be changed by in-game admin commands or world events

Settings outside that intersection (gameplay multipliers, nudity, XP rate, building decay, etc.) are operator-managed; axe stays out.

## Steam Server Query protocol background

`A2S_INFO` (`'T'` → `'I'`) carries: `Protocol`, `Name`, `Map`, `Folder`, `Game`, `ID` (appid), `Players`, `Max. Players`, `Bots`, `Server type`, `Environment`, `Visibility` (passworded), `VAC`, `Version`. Optional EDF fields: `Port`, `SteamID`, `SourceTV port+name`, `Keywords` (sv_tags), `GameID`.

`A2S_RULES` (`'W'` → `'E'`) returns N pairs of `Name`/`Value` strings — server's public cvars.

The Steam external server browser displays A2S_INFO fields as columns; the Conan in-game browser additionally decodes A2S_RULES. **Conan does NOT publish via the Keywords/sv_tags field the way ARK or Valheim do** — it publishes its server descriptor via A2S_RULES encoded identifiers (`S0`=PVPEnabled, `S1`=NoOwnership, … with `_b`/`_i`/`_f`/`_s` type suffixes). This is why server-browser filtering for Conan happens in-game, not in the Steam external browser.

## The eight descriptor settings

| Setting | File | Section | Key | Type | Notes |
|---|---|---|---|---|---|
| Server name | `ConanSandbox/Saved/Config/LinuxServer/Engine.ini` | `[OnlineSubsystemSteam]` | `ServerName=` | string | Engine.ini does not exist by default; axe creates it on first touch |
| Map | `Engine.ini` | `[/Script/EngineSettings.GameMapsSettings]` | `ServerDefaultMap=` | string (path) | Shorthands: `exiled` → `/Game/Maps/ConanSandbox/ConanSandbox`; `siptah` → `/Game/DLC_EXT/DLC_Siptah/Maps/DLC_Isle_of_Siptah`; any explicit `/Game/...` path passes through |
| Max players | **BOTH**: `Game.ini` `[/Script/Engine.GameSession]` AND `ServerSettings.ini` `[ServerSettings]` | (both) | `MaxPlayers=` | int | Both files must agree or the server silently disconnects clients on join. axe writes atomically to both. Game.ini doesn't exist by default; axe creates it. |
| Server password | `ServerSettings.ini` | `[ServerSettings]` | `ServerPassword=` | string | Empty string = no password (Visibility flag = 0) |
| PvP | `ServerSettings.ini` | `[ServerSettings]` | `PVPEnabled=` | bool (`True`/`False`) | Master PvP toggle |
| Region | `ServerSettings.ini` | `[ServerSettings]` | `serverRegion=` | int 0–5 | 0=EU, 1=NA, 2=Asia, 3=AU, 4=SA, 5=JP. axe accepts friendly names; writes the int |
| Community | `ServerSettings.ini` | `[ServerSettings]` | `ServerCommunity=` | int 0–4 | 0=Purist, 1=Relaxed, 2=HardCore, 3=RolePlaying, 4=Experimental. Playstyle classifier (distinct from PvP/PvE selector). axe accepts friendly names; writes the int |
| BattlEye | `ServerSettings.ini` | `[ServerSettings]` | `IsBattlEyeEnabled=` | bool | No command-line flag is needed on the dedicated-server side |

**AdminPassword** is intentionally excluded — it's not visible in any server browser. Operators manage it by direct INI edit.

## CLI surface

```
axe settings                            # show all eight current values in a Rich Table
axe settings name <string>              # get if no arg, set otherwise
axe settings map <exiled|siptah|path>
axe settings max-players <int>          # atomic write to BOTH files
axe settings password <string>          # empty string allowed
axe settings pvp <on|off>
axe settings region <NA|EU|AS|AU|SA|JP>
axe settings community <purist|relaxed|hardcore|roleplaying|experimental>
axe settings battle-eye <on|off>
```

Each setter ends with a hint: `restart the server to apply: axe server restart`. No auto-restart.

Each getter prints just the current value (one line) for scripting. Use `--json` for envelopes.

Bare `axe settings` shows a curated table:

```
axe / conan

setting        value
name           "Tay's Server"
map            exiled
max-players    40
password       <none>
pvp            on
region         NA
community      relaxed
battle-eye     on
```

## Module layout

- `src/axe/settings.py` — existing read module; gains `read_descriptor()` that returns a richer dataclass spanning all three files (Engine.ini, Game.ini, ServerSettings.ini).
- `src/axe/settings_write.py` — NEW. ~150 LOC. One function per setting, plus a transactional multi-file write for `max-players`.
- `src/axe/cli.py` — new `settings_app` sub-typer with eight commands (matches the `axe mods` sub-typer pattern).

## Read/write strategy

Stdlib `configparser` end-to-end. `optionxform = str` to preserve case. `strict=False` to tolerate UE quirks. Atomic write via existing `axe.io.atomic_write`.

For files that don't exist yet (Engine.ini, Game.ini): axe creates them with only the section + key it needs. Future setters add to existing sections.

For ServerSettings.ini (Conan auto-writes 200+ keys): configparser round-trip preserves all keys but may drift slightly on formatting. Acceptable because Conan rewrites the file at runtime anyway.

## MaxPlayers atomicity

```
def set_max_players(layout: Layout, value: int) -> None:
    """Write MaxPlayers atomically across Game.ini AND ServerSettings.ini.
    Rolls back if either write fails."""
    snapshot = _snapshot([game_ini, server_settings_ini])
    try:
        _write_game_ini_max_players(value)
        _write_server_settings_max_players(value)
    except Exception:
        _restore(snapshot)
        raise
```

`_snapshot` reads the current content of each file (or records "absent"); `_restore` writes back. If a process is killed mid-write, the atomic_write per file ensures no half-written file — at worst the two disagree, which `axe doctor` will catch (see below).

## `axe doctor` extension

Add a `max-players consistency` check: read both files, compare. Fail with a hint to run `axe settings max-players <N>` to reconcile. Cheap; ships in same PR.

## JSON envelope shape

```json
{
  "ok": true,
  "command": "settings name",
  "data": {
    "key": "name",
    "value": "Tay's Server",
    "previous": null,
    "files_written": [".../Engine.ini"]
  },
  "error": null
}
```

For bare `axe settings`:

```json
{
  "ok": true,
  "command": "settings",
  "data": {
    "name": "Tay's Server",
    "map": "exiled",
    "max_players": 40,
    "password": "",
    "password_set": false,
    "pvp": true,
    "region": "NA",
    "community": "relaxed",
    "battle_eye": true
  },
  "error": null
}
```

`password_set` is a derived bool so scripts can check the lock-icon equivalent without reading the value.

## What 0.4.0 explicitly refuses

- No free-form `axe settings set <Section.Key> <value>`. Curated surface only.
- No AdminPassword. Outside the filter.
- No gameplay knobs (XP, harvest, nudity, decay). Runtime-mutable.
- No tag/keyword editor. Conan doesn't use that A2S field.
- No A2S_RULES live inspection. Out of scope.
- No `axe settings rm` (revert to UE default). Operators delete by hand.
- No auto-restart on change. Operator triggers `axe server restart`.

## Password output convention

`axe settings password` (no value) prints `<none>` when empty and the plaintext otherwise. The JSON envelope always carries the raw `value` plus the derived `password_set` bool — scripts read `password_set` to check the lock-icon state without depending on the value.
